Repair MQTT Entities

Scan retained Home Assistant MQTT Discovery entries and compare them with the current generated SNMP2MQTT YAML. Only retained entries that prove Switch Vision SNMP2MQTT ownership through their topic, origin, IDs and state-topic contract are eligible for repair.

Safe scope: Scan is read-only. Repair never performs a broker-wide wipe and never edits Home Assistant .storage. A current valid generated SNMP2MQTT YAML is required so Switch Vision can distinguish current entities from historical ghosts.

Run a scan to check for historical Switch Vision MQTT entities.

Reset SNMP Discovery Data

Stronger cleanup for retiring SNMP switches or rebuilding the complete SNMP-generated state. It stops Switch Vision SNMP2MQTT, retires the exact retained discovery topics Switch Vision already knows about, deletes saved SNMP walk/capability/generated SNMP data, and clears the generated card. UniFi data and settings are preserved.

This is more destructive than Repair MQTT Entities. Use Repair first for stale Home Assistant entities. Reset is for a deliberate clean SNMP rebuild.

HP 3500yl Optical Diagnostics — SNMP SET

Warning: possible link disruption. SNMP SET is a privileged network-control command. Some HP diagnostic types (VCT and other) can interrupt active links. Switch Vision blocks those types and permits only live-verified DOM(1) on HP J8693A SFP ports, but firmware behaviour is not guaranteed. Test on a noncritical optical link first.

When enabled, clicking a supported optical SFP port automatically requests one bounded refresh and updates its Port dB field. Ordinary ports and every other switch model remain read-only.

Credential is stored privately by the Home Assistant Core integration, excluded from exports, and never returned to the browser. Leave blank to retain an existing saved value.
